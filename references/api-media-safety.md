# API 媒体归属与统计

三条聊天导出链路共用 `WeflowApiClient.fetch_messages`，canonical JSON 和占位符不新增字段。

- 无媒体调用保持原分页路径。带媒体的多日或无界调用先完整扫描同区间的无媒体消息，所有消息、所有页都参与 localId 查重；只要重复，就按本机日历的非空日分别重取。每次请求仍使用 `YYYYMMDD`，首尾日包含在内，每个实际响应页仍过 `guard_message_page`。同一天拆不开的撞号保留原有拒挂规则。
- 多日重取后按 `(serverId, localId)` 计数核对规划结果，缺失、多出或重复均拒绝发布；返回顺序恢复无媒体规划的原页序，canonical 继续按 `(createTime, localId)` 稳定升序。两遍之间有新消息时应重跑，不发布未经对账的集合。
- 单日不扫描拆段规划。无语音或语音没有本地路径时没有额外请求。每个实际页只有一条该 localId 的语音、路径在本轮未曾出现、且文件 mtime 严格晚于请求开始并不晚于结束时，按本页新写处理；mtime 等于请求开始、时间取不到或精度不足均进入旧缓存检查，不放宽时间窗口。已见路径集合跨本轮所有页和日段共享。
- 其他有路径的语音必须完成一次全会话无媒体扫描：本消息身份在扫描中存在，且该 localId 在全会话恰好只有一条语音，才允许使用缓存。发现另一条语音或扫描失败、身份缺失，一律拒挂，沿用“媒体缺失”占位，不转写。完整无界规划可直接复用。全会话扫描不复用跨运行的旧索引。它可增加单日耗时，但覆盖请求区间外的持久缓存撞号；不能以本次单日没有撞号来证明缓存正确。
- 仅读取上游缓存，不删除、改写它。响应无法直接区分缓存命中与新写；mtime 判据依赖本机时钟稳定且没有其他导出者同时写同一路径。单页内多条同 localId 语音不按 mtime 猜归属。日后上游提供完整身份文件名或可验证的归属字段时，应优先采用。

计数按消息记录，CAS 去重不减数：

| 字段 | 口径与报告位置 |
|---|---|
| `media_split_segments` | 因 localId 重复而发出的非空日段数，不是 HTTP 页数；未拆段为 0。daily 打 `export_chat_media_split:...:segments=N` 信息行；按需中文提示；批量汇总统计。拆段成功本身不产生失败 marker。 |
| `rejected_same_day_collisions` | 单日实际响应页内 localId 重复、且被原 guard 拒挂的记录数；它是原碰撞归属/类型不符计数的子集，不应与它们相加。 |
| `rejected_voice_cache` | 因旧语音文件无法证明归属而拒挂的记录数；与原 guard 的拒挂计数互斥，扫描失败也在此数中。 |

拒挂在 daily 的 `export_chat_media_rejected:` marker 增加 `same_day` / `voice_cache`；按需保持 exit 0 并提示补前诊断，批量返回上述三项并打印汇总。批量 plan 的非零日计数、块级续跑与产物存在性反查不变。

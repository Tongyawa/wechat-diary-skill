# processed Markdown 格式契约

> **这是数据契约，不是 prompt。** 任何消费 processed 的 prompt（本仓的日常二加、单会话总结，以及外部 sidecar skill）都引用本文件，不要各自复述——占位形态会随导出映射演进，复述必然各自过时。
>
> 修改前提：本文件描述的是**实际产出**，不是设计意图。改它之前先扫真实产物反推（见文末「怎么复核」）。

## 1. 文件与目录

- 路径：`<processed 根>/{私聊|群聊}_<会话名>/<yyyy-mm-dd>.md`。类型前缀（`私聊_` / `群聊_`）是契约的一部分。
- 下划线开头的目录（`_targets/` 等）是其他 skill 的旁路通道，公开 diary 一律跳过。
- 例外输入 `朋友圈_自己/<yyyy-mm-dd>.md`：不是聊天流，见 §4。

## 1.5 ⚠️ 群聊默认不是全量语料

日常导出的群聊 processed **默认经过上下文窗口过滤**：只保留本人发言前后一段时间窗口内的消息，当天本人完全没发言的群会被整体滤空。实测量级：开窗口后语料约为全量的 **12.5%**。私聊始终全量。

对消费方的影响：

- 写日记时这是**期望行为**（群里与本人无关的刷屏不该进日记）。
- **做单会话总结时这是陷阱**——你拿到的可能只是碎片，却看起来像完整记录。要完整群聊语料，用按需导出（默认不开窗口），或把工作区配置的 `[preprocessing.group_context_window].enabled` 设为 `false`。
- 群聊 md 内容稀疏、时间跳跃时，先怀疑是窗口过滤，不要断言「这天群里没人说话」。

## 2. 聊天流的行格式

每条消息一行 `发送者：内容`，「我」= 工作区配置里的本人。部分产物在消息前带一行时间戳。

正文里的方括号是**占位符**，表示非文本消息或结构化片段。

## 3. 占位符全表

### 3.1 引用（两种形态，务必区分）

| 形态 | 含义 | 怎么用 |
|---|---|---|
| `[引用 <发送者>：<被引原文>]` | 引用可解析，**带被引正文** | 当作对话上下文：这条回复是针对被引那句说的。被引正文是真实原文，可直接理解 |
| `[引用消息]` | 引用存在但**未能解析出原文** | 只知道「这是一条回复」，不要臆测被引内容 |

两种都很常见，不要只处理其中一种。引用与消息类型**解耦**——表情、语音也可能带引用。

### 3.2 图片：**方括号里装什么，取决于渲染模式**

同一个 `[图片：…]` 在不同产物里含义相反，**先判断你在读哪种产物，再决定怎么处理**。

| 产物 | 渲染模式 | `[图片：X]` 里的 X 是 | 怎么用 |
|---|---|---|---|
| **daily / 补跑的聊天流**（`私聊_*/` `群聊_*/`） | `ocr_inline`（默认） | **图片的文本化内容**（视觉描述优先，本地 OCR 兜底） | 直接当文字读。**不要拿它去 Read**——它不是路径 |
| **按需导出的聊天流**、朋友圈（`朋友圈_*/`）、下划线 sidecar 目录 | `preserve_paths` | **媒体相对路径**，视觉开启时追加 `｜<描述>` | `｜` 前的路径仍相对该 md 所在目录，可用 Read 精读原图 |

实际形态分别是聊天流的 `[图片：<视觉描述或 OCR 文本>]`（兼容旧契约写法 `[图片：<OCR文本>]`），以及 preserve_paths 产物的 `[图片：<相对路径>]` / `[图片：<相对路径>｜<视觉描述>]`。

本地 OCR 不外传；视觉描述会把图片和脱敏后的上下文上传第三方，因此默认关闭。

判据（不必依赖目录名也能分辨）：先按首个 `｜` 切开，左段形如 `media/...` 且以 `.jpg`/`.png`/`.mp4` 等媒体扩展名结尾的是路径；没有这种路径前缀的内容是视觉描述或 OCR 文本。

- `[图片]`（无冒号）：图片存在但 OCR 不可用、也没有可读的本地文件。
- `[视频：<相对路径>]`：视频，只出现在 `preserve_paths` 类产物里。

### 3.3 语音

| 形态 | 含义 |
|---|---|
| `[语音]` | 极少出现。**不要把它当主要情况处理** |
| `转文字失败` | 语音转写失败的实际占位 |

语音在转写可用时直接呈现为文字内容，不带占位。

### 3.4 表情

| 形态 | 含义 | 怎么用 |
|---|---|---|
| `[表情]` | 未具名的表情 / 表情包 | 无信息量，忽略 |
| `[捂脸]` `[可怜]` `[旺柴]` `[破涕为笑]` `[呲牙]` `[奸笑]` `[吃瓜]` `[OK]` … | **具名微信表情**，种类很多，本表不穷举 | **按语境当作正常对话内容处理**——它就是聊天里的一个表达，跟一句话一样看上下文。不要单独拎出来做情绪统计，也不要当噪声丢掉 |

判据：任何 `[<两到四个中文字>]` 且不在本文其它表格里的，基本都是具名表情。

### 3.5 应用类消息

文件占位有**三态**，注意大小用的是**全角括号 `（）`**（照抄自渲染器，别按半角去匹配）：

| 形态 | 含义 |
|---|---|
| `[文件：<文件名>（<大小>）]` | 附件，文件名与大小都拿到了 |
| `[文件：<文件名>]` | 附件，有文件名但没有大小 |
| `[文件]` | 附件，但原始数据没有文件名字段——**不要编造文件名** |

文件名往往有实质信息（课程名、截止日期、材料名），值得读进 DoneList / ExtraNotes。

其余应用类：

| 形态 | 含义 |
|---|---|
| `[链接]` | 分享的网页链接（部分带标题） |
| `[小程序]` | 小程序卡片 |
| `[视频号]` | 视频号内容 |
| `[视频分享]` | 普通视频分享 |
| `[合并转发]` / `[聊天记录]` | 合并转发的聊天记录 |
| `[接龙]` | 群接龙 |
| `[动态]` | 动态卡片 |
| `[收藏]` | 收藏内容 |
| `[分享]` | 其他分享卡片 |
| `[音乐]` | 音乐卡片 |
| `[群公告]` | 群公告 |
| `[转账]` / `[红包]` | 转账或红包提示 |
| `[其他消息]` | 未归类的消息类型。**这是信息洞不是内容**，不要据此推断任何事 |

除文件三态外，上表中的应用类标签可以在方括号后附标题或摘要；链接还会写成 `[链接：<标题>]`。标签决定类型，尾随文字才是该卡片带出的可读信息。

### 3.6 本表不完整

当前 renderer 对以下基础类型会输出稳定的裸标签：`[名片]`、`[视频]`、`[位置]`、`[通话消息]`、`[系统消息]`。它们按字面语义理解；`[视频]` 不等于 preserve_paths 产物中的 `[视频：<相对路径>]`。

上表是按真机高频反推的，**不是穷举**。微信仍可能出现未列出的类型或新变体。

遇到本表没有的方括号内容：**按字面语义理解，不要猜测结构，也不要假定它是路径或可 Read 的东西**。若该类型频繁出现且影响产物质量，按 §6 扫一遍并把结论补进本表。

### 3.7 系统与提示

| 形态 | 含义 |
|---|---|
| `[撤回]` 类 | 撤回提示 |
| 拍一拍文本 | 群内互动提示 |

## 4. 朋友圈流（`朋友圈_自己/<date>.md`）

不是聊天流。每条动态一个块：时间、正文、媒体、评论、位置。

- 媒体路径**相对于该 md 所在目录**（即 `朋友圈_自己/media/...`）。
- 用 Read 工具读真实媒体做多模态理解。**不要因为路径存在就写成「发了一张图片」**，也不要把路径当成 OCR 文字。

## 5. 版本漂移警告

**同一语义的占位字符串在版本间变过。** 实测：早期产物写 `[转发的聊天记录]`，现役写 `[合并转发]`。所以：

- **消费方不要硬编码字符串做精确匹配**，按语义分类处理。
- 归档库里的历史产物**不会**因导出映射升级而重生——同一批数据里可能新旧形态共存。

## 6. 怎么复核这份契约

改导出映射后、或怀疑本文过时时，扫真实产物反推，别照记忆改：

```powershell
# 把 <根> 换成 processed 根或归档 processed 根
python -c "import re,collections,pathlib,sys; r=pathlib.Path(sys.argv[1]); c=collections.Counter(); [c.update(re.findall(r'\[([^\[\]\n]{1,80})\]', p.read_text(encoding='utf-8'))) for p in r.rglob('*.md')]; [print(f'{n:>6}  {k}') for k,n in c.most_common(60)]" <根>
```

**两个根都要扫**：live processed 反映现役映射，归档 processed 反映历史形态，两者并集才是消费方实际会遇到的全集。

**而且必须按产物类型分段扫**（聊天流 / 朋友圈 / sidecar 各扫一遍），不要把全树混在一起看样例——同一个占位在不同产物里含义可能相反（见 §3.2 的图片），混扫后从单一样例归纳会得出完全错误的结论。
